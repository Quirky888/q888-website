# Q888 Project Expression Skill

## Inputs

Determine:

- project name;
- human purpose;
- audience;
- working mode;
- active expression lenses;
- expression levels from 0–5;
- intentional strangeness;
- practical requirements;
- safety and accessibility constraints.

Use an existing file under `digital-dna/projects/` when available.

## Process

1. Follow `AGENTS.md` for rule ownership and selective reading; use the core DNA and expression lenses already read or load them when needed.
2. Read the matching project overlay, reusing it if already understood in this session.
3. Identify what must remain practical.
4. Identify what is explicitly allowed to become strange.
5. Choose productive tensions to keep visible.
6. Describe the intended phenotype in one sentence.
7. Implement a stable internal structure.
8. Let the selected expression occupy the visible surface at the requested intensity.
9. Check for flattening, random decoration, cold terminal theatre, and unreadable source code.
10. Validate both functionality and voice.

## Output declaration

For substantial expression work, briefly identify the working mode, expression
lenses, matching overlay, and intended feeling when they affect the decision.
Use a short sentence; skip this declaration for tiny tasks.

## Important distinction

Surface language may be mythic, mushroom-soft, bureaucratically satirical, or cosmic.

Source-code names should remain clear unless a domain term genuinely improves meaning.
